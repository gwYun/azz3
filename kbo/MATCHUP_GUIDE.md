# 야구 승부 예측 (`/matchup`) 가이드

두 KBO 팀이 맞붙으면 누가 이길지, 확률은 얼마인지 예측하는 페이지입니다.
이 문서는 **처음 보는 사람도 이해할 수 있도록** 무엇을 보여주는지, 어떻게 쓰는지,
안에서 어떻게 계산하는지를 설명합니다.

- **위치**: 웹사이트 상단 `승부 예측` → `KBO 승부예측` 탭 (`/matchup`)
- **한 줄 요약**: 실제 전 구단 로스터로 예상 라인업을 짜고, **경기를 100만 번
  시뮬레이션**해서 승부를 예측합니다.

---

## 1. 무엇을 볼 수 있나

두 팀(홈/원정)을 고르면 아래가 나옵니다.

| 항목 | 설명 |
|---|---|
| **승리 확률** | 홈팀 vs 원정팀 승률을 막대로 표시 (예: 삼성 50.9% · 한화 49.1%) |
| **예상 스코어** | 양 팀의 기대 득점 (예: 5.1 : 5.0) |
| **득점 분포** | 각 팀이 0점, 1점, 2점… 낼 확률을 막대그래프로 표시 |
| **예상 라인업** | 각 팀이 실제로 낼 법한 9인 타순 |
| **승리확률 최대 라인업** | 그 경기에서 **이길 확률이 가장 높은** 타순 (예상 대비 몇 점 이득인지 함께 표시) |
| **선발·불펜** | 그 경기의 선발 투수와 **투입 가능한 불펜**(및 쉬는 투수) |

각 선수 옆 숫자:
- **wRC+**: 타자 종합 성적. **100이 리그 평균**, 높을수록 잘 치는 타자.
- **출루율(OB%)**: 타석에서 아웃되지 않고 나갈 확률.
- **FIP**: 투수 성적. ERA처럼 **낮을수록 좋음**.

---

## 2. 어떻게 사용하나

1. **홈 팀 / 원정 팀 선택** (⇄ 버튼으로 홈·원정을 바꿀 수 있음)
2. **시리즈 경기 (1~5)**: 3연전·5연전에서 몇 번째 경기인지 고름.
   경기를 바꾸면 **선발 투수가 로테이션대로 바뀌고**, 앞 경기에 던진 불펜은
   **쉬는 것으로 처리**됩니다.
3. **승리확률 최대 라인업**: 켜면 양 팀이 각자 최적 타순으로 붙었을 때의 결과를 봄.
4. **후반 불펜 레버리지**: 켜면 접전 후반에 각 팀 **최고 불펜 투수**를 투입하는 것으로 계산.

바꿀 때마다 브라우저에서 즉시 다시 시뮬레이션합니다.

---

## 3. 안에서 어떻게 작동하나 (쉽게)

크게 **"재료 준비(파이썬) → 경기 시뮬레이션(브라우저)"** 두 단계입니다.

### 3-1. 재료 준비 — 실제 데이터

- KBO 공식 기록 페이지(`/Record`)에서 **전 구단 전체 선수**의 이번 시즌 성적을 가져옵니다.
  (규정 타석 리더보드는 팀당 2~6명뿐이라, **팀 필터를 하나씩 돌려** 벤치까지 포함한
  실제 로스터 전체를 확보합니다. 예: 키움도 39명 전체 확보.)
- 각 선수의 성적을 **한 타석당 결과 확률**(볼넷/1루타/2루타/3루타/홈런/아웃)로 변환합니다.
- 결과는 `kbo-matchup.json` 파일 하나로 저장됩니다. (선수 능력치·투수·로테이션 등 "재료"만
  담고, 승부 결과는 담지 않음 — 계산은 브라우저가 함.)

### 3-2. 경기 시뮬레이션 — 타순까지 반영

브라우저에서 다음 순서로 계산합니다.

1. **타자 × 투수 대결 확률 (log5)**: 타자의 능력과 그날 상대 투수의 능력을 합쳐,
   이 타석에서 안타/홈런/아웃이 나올 확률을 계산합니다. 강한 투수를 만나면 홈런·안타
   확률이 낮아집니다.
2. **베이스-아웃 시뮬레이션 (타순 반영)**: 주자와 아웃 상황을 두고 **1번부터 9번까지
   타순대로** 한 타석씩 진행하며 득점을 쌓습니다. 이닝이 넘어가도 타순은 이어지므로
   **누가 몇 번에 치느냐(타순)가 득점에 영향**을 줍니다. → 이게 "최적 라인업"이 의미 있는 이유.
3. **점수 → 승부**: 야구 득점의 실제 들쭉날쭉함에 맞춘 분포(음이항)로 양 팀 점수를
   뽑아 비교합니다.
4. **100만 번 반복 (몬테카를로)**: 위 경기를 브라우저에서 100만 번 돌려 승률과 득점
   분포를 만듭니다. (화면 멈춤 없이 백그라운드에서 실행)

### 3-3. 반영하는 변수

- **홈 이점**: 홈팀 득점 +10% (실제 KBO 홈 승률 ~53.8%에 맞춤).
- **상대 선발 투수**: 초반 이닝은 그날 선발의 능력으로 계산.
- **불펜 + 후반 레버리지**: 후반 이닝은 불펜으로 교체, 접전이면 최고 투수 투입.
- **로테이션**: 시리즈 경기마다 선발이 바뀌고 **연속 등판하지 않음**.
- **불펜 피로도** (핵심): 상위 불펜 투수가 앞 경기에 던졌으면 **다음 경기엔 쉬는 것으로**
  처리 → 상대가 만나는 불펜이 약해짐. (예: 삼성 1차전에 최지광·김재윤이 던지면 2차전엔
  두 명이 빠진 불펜으로 계산)

### 3-4. "이길 확률이 가장 높은 라인업"은 어떻게 찾나

상대가 정해지면 **득점이 높을수록 승률도 높다**는 성질을 이용합니다. 그래서 무거운
100만 번 시뮬레이션 대신, 빠른 기대득점 계산으로 **타순을 조금씩 바꿔가며(스왑) 기대
득점이 가장 높은 순서**를 찾습니다. 실제로 타순 효과는 크지 않아, 예상 라인업 대비
보통 **경기당 +0.1점 안팎**의 차이가 납니다(과장하지 않고 그대로 표시).

---

## 4. 무엇이 "실제"이고 무엇이 "모델"인가 (중요)

정직하게 구분합니다.

- ✅ **실제 데이터**: 전 구단 선수들의 이번 시즌 성적·로스터 (KBO 공식 기록).
- 🔷 **모델(추정)**: **타순, 선발 로테이션 순서, 불펜 가용성**.

왜 모델이냐면, **실제 경기별 라인업지·예고 선발·투수 기용 기록은 KBO의 `/ws/` API에만
있고, 이 API는 robots.txt가 차단**하고 있어 가져오지 않기 때문입니다. (statiz를 쓰지
않는 것과 같은 원칙.) 그래서 "직전 경기의 실제 불펜"이 아니라, **실제 선수들을 바탕으로
합리적으로 모델링한 가용성**을 씁니다.

- 포지션 정보도 기록 페이지에 없어, 라인업은 **출전·성적 순**으로 구성합니다(수비 포지션
  제약 없음).
- 파크팩터(구장 효과)는 반영하지 않습니다.

## 5. 개발자용: 실행·재생성

데이터를 최신으로 갱신하고 예측 재료(JSON)를 다시 만들려면:

```bash
# 1) 전 구단 전체 로스터 + 팀 합계를 최신으로 내려받기 (캐시)
python -m kbo.scripts.fetch_data

# 2) 매치업 재료(JSON) 재생성 → web/public/kbo-matchup.json 로 복사됨
python -m kbo.scripts.run_matchup --season 2026

# 3) 웹 확인
cd web && yarn dev   # http://localhost:3000/matchup
```

테스트:

```bash
python -m pytest tests/test_kbo_v2.py -q     # 파이썬 (매치업·엔진)
cd web && yarn vitest run lib/matchup-sim.test.ts   # 타입스크립트 엔진 + 파이썬↔TS 검증
```

### 파일 구조

| 파일 | 역할 |
|---|---|
| `kbo/src/data.py` | `player_batting_full`/`player_pitching_full` — 팀 필터로 전체 로스터 수집 |
| `kbo/src/matchup_export.py` | 선수 확률·투수 기용·로테이션·라인업 계산, JSON 조립. **파이썬 시뮬 기준 구현**도 여기(테스트 검증용) |
| `kbo/scripts/run_matchup.py` | 실행 스크립트 → `web/public/kbo-matchup.json` |
| `web/lib/matchup-sim.ts` | 브라우저 시뮬레이션 엔진 (log5 · 베이스-아웃 마르코프 · 승률 · 최적 라인업 · 불펜 가용성) |
| `web/lib/matchup.worker.ts` | 100만 번 몬테카를로 (백그라운드 워커) |
| `web/app/matchup/page.tsx` | 화면(UI) |
| `web/components/Nav.tsx`, `web/lib/i18n.ts` | 탭 추가, 한/영 문구 |

> **검증 팁**: 파이썬 계산 로직과 브라우저 TS 엔진은 **완전히 같은 값**을 내도록 고정
> 데이터(`web/lib/__fixtures__/markov-parity.json`)로 소수점까지 대조합니다. 한쪽을
> 고치면 다른 쪽도 맞춰야 테스트가 통과합니다.

---

## 6. 한계 및 다음 단계

- 타순·로테이션·불펜 가용성은 **모델링**이라 실제 라인업지와 다를 수 있습니다.
- 진짜 예고 선발·경기별 기용을 쓰려면 `/ws/` API(robots 차단) 사용 승인 또는 외부
  데이터 소스가 필요합니다. 그 경우 경기별 로스터 DB + 요청 시 증분 갱신 설계가 의미
  있어집니다.
- 데이터는 스크립트를 다시 돌릴 때 갱신되며, 페이지 접속 시 자동 갱신은 하지 않습니다.
